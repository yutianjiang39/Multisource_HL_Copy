# 验证与证据

[English](en/testing.md) · [性能与规模](performance.md) · [项目首页](../README.md)

项目的优势应由功能、实测结果和必要条件共同表达。本页说明公开证据的类型，帮助读者判断每个数字能够支持什么结论。

## 四类证据

| 类型 | 本版内容 | 可以支持的结论 |
| --- | --- | --- |
| 主网测量与运行摘要 | 本地提交分位数、端到端中位数、3 目标运行摘要 | 记录时段和样本内观察到的性能与运行规模 |
| 模拟负载验收 | 双来源 150/s、5 秒脉冲、10 轮结果 | 指定负载与模拟环境下的请求匹配和尾延迟 |
| 配置与能力说明 | 最多 8 个可配置目标、功能与职责说明 | 所提供配置的支持范围；不等于满载上限 |
| 合成体验与文件检查 | 场景图、examples/、本地校验 | 展示体验、文件结构与披露规则 |

主网指标、模拟指标与配置上限不混为同一种证据。真实历史数字统一放在 [benchmarks/](../benchmarks/README.md)，虚构示例放在 [examples/](../examples/README.md)。

## 本版做过的核对

- 对照项目保留的结果汇总核对数值、样本数和单位。
- 核对本地提交、模拟端收到请求、交易所入块与成交等不同时间边界。
- 区分合计输入速率、单来源速率、请求匹配比例和真实成交率。
- 核对目标配置上限与实际演练、实盘规模。
- 保留未测项目和不支持外推的条件，避免把局部最佳结果写成全系统保证。
- 删除与结果理解无关的身份、部署、原始数据和内部机制。

本次是对既有记录的整理和公开化，没有重新运行私有引擎、生产压测或实盘交易。历史版本的结果不自动证明当前版本的表现。

## 公开测量应包含的最小信息

指标名称、起止边界、单位、样本或轮次、负载与窗口、主网或模拟类型、版本适用范围，以及会改变解释的重要限制。

硬件类别、CPU 等级或系统负载可以在脱敏后公开，有助于公平比较；现有历史摘要没有完整保留这些字段，因此本版明确缺失，不补造环境。无需公开主机位置、访问方式或具体调优参数。

后续可以增加当前版本 p95/p99、持续吞吐、8 目标活跃负载、错误率和积压峰值。它们是待测项目，不用合成数值代替。

## 本地检查

使用 Python 3.10 或更高版本：

```bash
python3 tools/check_public.py
python3 tools/check_public.py --self-test
python3 tools/package_public.py --output ../Multisource_HL_Copy-public.zip
```

检查器核对发布清单、相对链接、JSON 分类与必要测量字段、SVG 结构及常见敏感模式。它允许经过整理的 measured_aggregate，不把真实指标强制标成 synthetic。

CI 重复文件检查，不能重跑私有实验、验证原始交易或发现所有误导性统计。文件检查通过与性能验收通过是两件不同的事。

## 结果如何更新

更新指标时同时更新中英文页面、[results.json](../benchmarks/results.json) 和 [性能图](../assets/performance.svg)。保持指标定义一致；定义或样本范围变化时另列结果，不把新旧数据直接拼接。原始证据在私有侧保留，公开侧提供脱敏统计、清楚口径与适用边界。
