# 测试体系与统计口径

这一页说明项目怎么验证、公开的数字按什么口径统计。只给汇总结论，不提供逐笔记录、原始日志或事件时间线。

## 验证分层

| 层级 | 做什么 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **单元测试** | 配置校验、风控判断、报告计算、控制命令等单个模块 | 模块按约定工作 | 模块之间的配合 |
| **内核场景测试** | 用构造的来源与本方事件驱动 Rust 执行内核，检查委托、状态和风控记账 | 竞态、部分成交、断线、重启等路径的行为符合设计，可重复运行 | 真实交易所的接受与成交 |
| **模拟交易所** | 执行程序接一个测试用的模拟交易所，端到端跑完整流程 | 进程级的启动、停止、恢复与持久化 | 真实网络时延与交易所规则 |
| **dry_run 演练** | 来源读主网真实动作，本方用本地账本模拟成交 | 真实来源节奏下的跟随决策、风控与报告 | 真实成交、保证金与收益 |
| **影子测试** | 脚本控制的测试钱包作来源，跟单程序在主网小额实盘运行 | 主要路径在真实交易所上可用，时延可测 | 真实来源的行为分布、长时间运行 |
| **实盘运行** | 真实来源、主网小额账户 | 在真实条件下长期运行的表现 | 大资金与极端行情 |

能力状态的三层用词（已实现 / 已部署 / 实盘验证过）就是按这张表来的：只经过前四层的，最多写「已部署」。

## 公开统计的口径

- **只给汇总。** 不按来源、币种或账户拆分；不公开单笔订单和事件时间线。
- **写明条件。** 每个数字都标注日期、环境（模拟 / 影子 / 实盘）、样本范围和测试时的版本；不同条件下的数字不直接比较。
- **规模只给量级。** 账户资金、单笔金额只写「小额」「接近交易所最小单额」这样的量级，不给精确值。
- **时延统一按交易所时间戳。** 端到端时延从来源委托生效算到镜像委托生效，两端都用交易所时间戳，不受服务器时钟偏差影响；分段时延另行注明计时来源。
- **不代表收益。** 执行时延和可靠性只说明系统跟得上、对得上账，不说明跟单能赚钱。
- **版本会过期。** 测试之后的修复不会自动让旧结果对新版本成立；没有重测的会写明。
