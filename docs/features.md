# 功能说明

每一项写清楚场景、效果和限制。状态用词：

- **已实现**：代码完成、有自动化测试。
- **已部署**：代码已在服务器上，可以随时启用。
- **实盘验证过**：用真实来源在主网跑过，并逐项核对过结果。

截至 2026-11-21，私有仓库在服务器上的全量测试：Python 471 个、Rust 326 个，全部通过。测试数量只说明验证的工作量，不代表没有缺陷。

## 1. 多来源跟单

**场景：** 想用一个账户同时跟几个风格不同的钱包，又不想几个来源在同一个币上互相打架。

**效果：**
- 每个来源有自己的跟随比例，共用同一套账户级风险上限。
- 同一个币在同一时间只归一个来源：先发出信号的来源取得这个币；本方在这个币上没有仓位、没有挂单、也没有待处理的跟随动作后，归属才释放。
- 被屏蔽的信号单独计数，报告里和「漏跟」「风控拦截」分开列。

**限制：** 不做同一个币上多个来源的叠加或净额合并；只支持按比例跟随。

**状态：** 实盘验证过。2026-11-19 用三个来源跑过约 80 分钟的小额实盘；运行中暴露的一个推送先后问题已经修复，修复后的版本已部署，还没有再次实盘验证。

## 2. 订单全程跟随

**场景：** 来源的挂单、改价、撤单、成交、减仓需要尽快、按比例反映到本方。

**效果：**

| 来源动作 | 本方动作 |
|---|---|
| 新挂单 | 按比例挂只做 Maker 的镜像单，价格按配置向外偏移 |
| 只改价 | 原地改价，不撤了重挂 |
| 撤单 | 撤掉镜像 |
| 吃单开仓 | 按来源成交价加滑点上限，用 IOC 跟随开仓 |
| 减仓 / 清仓 | 按来源减仓比例只减仓；来源归零时本方一次平掉 |
| 来源已不持有而本方还有 | 定时扫描加事件触发，只减仓平掉残仓 |

- 每个来源订单只被认领一次，崩溃重启也不会重复下单。
- 已经发出、但结果不明的委托不会自动重发，要等到确证的终态。

**限制：** 只跟永续合约的普通委托，不跟现货、触发单。按比例缩小后低于交易所最小金额的单会被跳过或按配置补足。

**状态：** 实盘验证过（见 [效果展示](showcase.md) 场景一）。之后修复的多处竞态与部分成交的边界情况已部署，还没有在实盘复核。

## 3. 风险控制

**场景：** 来源大幅亏损、本方与来源方向背离、出现不是本程序下的挂单时，需要及时停下来。

**效果：**
- 交易程序在内存里实时估算净值，从本次运行的最高点回撤超限并持续一小段时间后，自己停止并平仓。资金转入转出不影响净值。
- 一个独立的守护进程定期从交易所核对，规则和程序内的一致，作为兜底；另外检查账户合计仓位、方向与偏差、非本程序挂单。
- 不同事件分别执行三种动作：**暂停新增**、**撤单但保留仓位**、**平仓**。每次动作都会推送通知。

**限制：** 不公开阈值和计算细节。止损按市场成交，实际平仓价格可能比触发时更差；风控不承诺收益，也不保证一定能在某个亏损额内平掉。

**状态：** 程序内止损和外部守护都已部署，实盘运行时常驻；触发路径由自动化测试覆盖。

## 4. 运行中调整

**场景：** 跟单进行中想改比例、上限或开关，或者换一个来源。

**效果：** 每次修改先预览，系统给出它属于哪一级：
- **即时**：比例、上限、跟随开关等，下一单起生效，不停顿。
- **重建**：跟随的币种范围、并发档位等，撤掉本程序挂单、保留仓位，几秒到几十秒后按新参数恢复。
- **切换来源**：本方必须先空仓、无挂单；旧状态归档，止损的净值和峰值沿用。

修改的结果只有四种：已应用、被拒绝、失败、已回滚，都会写审计记录。新配置起不来时自动回到原配置。

**限制：** 账户、网络、运行模式等不能在运行中改，要停止后修改。

**状态：** 即时调参在 2026-11-19 实盘用过一次（修改止损上限），按预期生效。之后把更多字段改成即时级，这部分已部署，还没有实盘验证。来源切换只在测试中验证过。

## 5. 异常恢复

**场景：** 行情推送断线、交易所请求超时、进程异常。

**效果：**
- 有两路独立的数据源。一路断线、另一路仍在推送时，减仓和清理照常进行。两路都断时暂停新增，已挂镜像按宽限期处理。
- 断线恢复后重新读取并核对；对不上的币单独标记，等核实后再继续。
- 结果不明的订单不自动判成功或失败，必要时由人工按记录处理。
- 停止时依次执行：停止新增 → 撤单 → 核对 → 写盘。

**限制：** 不是所有故障都能自动恢复。进程异常退出不会自动重启，会推送告警，由人决定下一步。

**状态：** 已部署，实盘运行期间一直在用。

## 6. 报告与提醒

**场景：** 没有管理面板，人不会一直盯着，需要系统主动告诉人发生了什么。

**效果：**
- 实时事件：开仓、加减仓、平仓（含持仓时长和已实现盈亏）、反手、保证金占用、回撤预警、跟单异常。合并推送，并限制每分钟条数。
- 定时报告：复刻度、与来源的偏差、成交价格与延迟、本周期和累计盈亏、漏跟与风控拦截，以及「需要关注」。
- 服务器上的 AI 助手只读日志和指标，在报告里写一段异常原因分析。

**限制：** 没有网页面板。[效果展示](showcase.md) 里的报告图是用合成数据重排的示意，不是真实界面截图。

**状态：** 已部署，实盘使用中。

## 7. dry_run 演练

**场景：** 新来源、新参数，先看看跟起来是什么样，但不想真下单。

**效果：** 来源仍然读主网的真实动作，本方换成本地账本模拟成交和余额，跟单流程、风控和报告照常运行。

**限制：** 演练结果不能证明真实成交、保证金或收益。交易所会不会接受这张单、能不能成交，只有实盘才知道。

**状态：** 已部署，多次使用。

## 8. 滚动事故记录

**场景：** 出了问题以后，要知道当时系统收到了什么、做了什么决定。

**效果：** 运行时把执行核心的全部输入和对交易所的调用记成压缩分段，写盘在后台进行，不拖慢交易。每个实例只保留最近一段（有容量上限，超出删最旧的）；队列满时丢掉一段并标记，记录继续。可以按需取回某次运行的记录用于排查。

**限制：** 只保留近期记录，不是永久存档。离线回放功能已从主体中移出，现在只记录、不重放。

**状态：** 已部署，还没有在实盘运行中产生过记录。
