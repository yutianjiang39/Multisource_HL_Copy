# Public showcase roadmap

[中文](../roadmap.md) · [Project home](../../README.en.md) · [Scenario guide](showcase.md)

This page describes ways the public showcase materials could improve. It is not the private product's development schedule and does not establish that a capability is implemented, deployed, or live-verified. Items carry no delivery dates or commitments.

## Current public materials

| Material | Purpose |
|---|---|
| Chinese and English documentation | Introduce the product context, capability scope, and limitations |
| Conceptual overview and scenario illustrations | Help visitors understand information relationships |
| Synthetic scenario, report, and event data | Provide readable fictional examples for documentation discussions |
| Public-scope and verification notes | Distinguish presentation content from facts requiring separate evidence |
| License and historical-license notes | Explain the applicable terms for using the materials |

Together these form a readable showcase package, not an executable trading system. Start with [Features](features.md), the [Scenario guide](showcase.md), and [PUBLIC_SCOPE.md](../../PUBLIC_SCOPE.md).

## Priority improvements

### 1. Reading paths and terminology

Help first-time visitors move from “what the project is” through “which capabilities it discusses” and “how to read the examples” to “where the evidence ends.” Keep terminology aligned across Chinese, English, illustrations, and data.

### 2. More complete synthetic scenarios

Expand fictional situations around multiple-source context, state changes, incomplete information, and human review. New examples should explain what a reader can observe and which conclusions remain unsupported, without becoming real configuration or operating tutorials.

### 3. Documentation and example consistency

Keep illustrations, scenario prose, and synthetic data aligned. Add field explanations, reading order, and relationships between examples where helpful, without presenting public data formats as production interface contracts.

### 4. Clearer evidence labels

Continue distinguishing capability descriptions, conceptual illustrations, and synthetic examples. Any future verifiable public statement should identify its scope and basis. Fictional numbers must not fill gaps in evidence.

### 5. Accessibility and reading experience

Improve image alternative text, heading structure, mobile reading, and bilingual navigation. Relevant limitations should appear near the material they qualify, rather than depend on a reader reaching the end of a page.

## Possible showcase themes

| Theme | Reading experience to improve |
|---|---|
| Explanations | Distinguish known facts, interpretations, and open questions more easily |
| Before-and-after change views | Understand which information a settings discussion would affect |
| Report hierarchy | See important points first, then locate the related context |
| Scenario coverage index | Know which questions already have synthetic examples and which remain unillustrated |

These are content directions, not feature-release plans, and do not establish the private system's design.

## What the public package is not intended to provide

- A runtime that connects to accounts or executes trades.
- Real account configuration, trading parameters, or deployment procedures.
- Private execution, allocation, risk-control, or fault-handling implementations.
- Production logs, individual trading records, account history, or source research.
- Synthetic scenarios presented as live-operation, performance, safety, or return evidence.

## Suggesting improvements

A suggestion can focus on one clear reading problem: an unclear passage, a fictional situation that would help explain a concept, or a mismatch between Chinese and English. Improvements that help visitors distinguish sources, actions, outcomes, and evidence boundaries are particularly useful.

New public materials remain subject to [Public scope](../../PUBLIC_SCOPE.md) and [LICENSE](../../LICENSE). Roadmap updates describe changes to the showcase, not releases of the private implementation.
