# 常见问题

## 关于仓库

### 这个仓库是什么？

这是 Multisource HL Copy 的公开成果展示包，介绍多来源协作能力，并提供有记录依据的历史性能与验证汇总。内容包含文档、性能图表、概念图与静态合成例子。结果证据与私有生产实现的边界见 [PUBLIC_SCOPE.md](../PUBLIC_SCOPE.md)。

### 下载后可以开始交易吗？

不可以。仓库没有交易运行时、账户接入、密钥配置或部署入口。阅读 JSON、查看图片或运行公开材料检查，都不会连接交易账户或提交委托。

### 为什么保留能力介绍，却不公开实现？

能力介绍解释使用场景和产品取舍，历史测量汇总展示可观察的工程成果。延迟、突发吞吐率、并发来源数与测试覆盖可以连同必要测量背景公开，不必公开算法、运行参数或生产配置。具体成绩以对应记录的版本与范围为准。

### “公开仓库”是否意味着所有材料都可以任意使用？

使用条件取决于适用许可，不由是否可以公开访问决定。请阅读根目录的 [LICENSE](../LICENSE) 及其中指向的历史许可说明。展示材料也不授予私有代码或服务的访问权。

## 关于测量数据、图示与合成场景

### 示例是不是把真实日志里的名称换掉了？

`examples/` 中的场景不是。它们从空白构造，使用虚构来源、资产、状态与示例值，并标为 **SIMULATED / 合成示例**，JSON 声明 `data_classification: synthetic`。另行发布的 [测量汇总](../benchmarks/results.json) 来自有记录依据的历史测量，分类为 `measured_aggregate`；它们不是合成场景，也不包含原始事件轨迹。

### SOURCE_A 或 ASSET_X 能对应到真实账户或资产吗？

不能。它们是虚构标签，不提供真实钱包、账户、市场或资产的映射。不要把这些标识替换成真实地址来尝试运行示例；本仓库没有这样的运行功能。

### 图片是产品的实际管理界面吗？

概念图用于表达场景与信息关系，不是实际管理界面的截图。[性能图表](../assets/performance.svg) 则可视化已公开的测量汇总，其依据与口径见 [性能与验证](performance.md)。图片的性质取决于对应数据与说明，不应把所有图示都当成合成数据或实时界面。

### JSON 是生产 API、配置模板或可导入的策略吗？

不是。[场景](../examples/scenario.json)、[报告](../examples/report.json)与[风险事件](../examples/risk-event.json)是合成阅读材料；[测量汇总](../benchmarks/results.json)保存可公开的历史聚合指标。两类 JSON 都是文档数据，不是生产 API、可执行配置或策略规则。

### 示例中的数值可以用来比较性能或收益吗？

`examples/` 中的合成值不可以。它们用于解释场景，没有真实测量基础。性能分析应使用标为 `measured_aggregate` 的结果，并同时阅读测量边界、历史归属与已知限制；这些工程指标本身不衡量收益。

## 关于能力与证据

### 功能页能证明哪些能力已上线吗？

单独的 [功能说明](features.md)用于介绍能力。[性能与验证](performance.md)提供有记录依据的结果证据，支持其中明确列出的历史范围。历史测量不自动证明当前版本的所有功能均已上线或重新验证。

### 公开性能基准可以展示哪些信息？

可以展示有记录依据的延迟分位数、突发信号吞吐率、实测并发来源数、测试类别及汇总计数。匿名化环境类别、通用测量起止边界、样本量、持续时间、被测目标数和错误率或丢弃率也可以公开；这些背景帮助读者判断结果的适用范围。记录缺失的字段应明确说明，不能补造。见 [基准数据说明](../benchmarks/README.md) 与 [验证范围](testing.md)。

### 怎样理解 p99、突发吞吐率和来源数量？

p99 必须来自相应记录，不能从 p50 或平均值推算。以 signals/s 表示的突发吞吐率须对应明确的处理层与测量窗口，不等于交易所每秒委托数或成交数。实测并发来源数说明该次测试覆盖了多少来源，不自动等于最大支持数量；被测目标数、来源数与样本量也不是同一个统计单位。

### 这些数字是最新版本的结果吗？

以每项结果标注的历史时期、版本和验证范围为准。本包记录历史测量时会保留其历史属性；文档更新日期不等于引擎重新测试日期。补充新测量时应新增或明确更新对应记录，并保留可理解的版本归属。

### 公开检查脚本验证什么？

在仓库根目录、使用 Python 3.10 或更新版本运行：

```bash
python3 tools/check_public.py
```

该脚本检查公开包的文件、分类、引用和披露规则，具体检查项以脚本内容为准。它帮助维护材料的一致性，不会重新运行交易引擎或复测历史指标，也不替代独立审计。

### 一个风险示例显示“已处置”，能说明真实风险已消除吗？

不能。示例状态是虚构情境的一部分。它既不证明市场上的动作会按时完成，也不建立真实事件与处置动作的固定对应关系，更不能保证损失上限。

## 关于历史、反馈与报告

### 替换当前 ZIP 能删除以前已经公开的内容吗？

不能。更新当前文件不会自动改写 Git 历史、已有发布附件、分支、派生副本、缓存、截图或其他人的下载。本包只描述当前提供的材料，不能承诺旧公开内容已经消失；适用的既有许可权利也不能仅因更新 ZIP 被视为不存在。

### 可以贡献什么？

欢迎改进文档、翻译、图表与合成场景，也欢迎按公开边界补充有记录依据的脱敏测量汇总。测量结果应写明口径与历史归属，合成场景应保留分类；不加入生产实现、真实配置、地址、账户记录或日志。详见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

### 想证明某个问题，可以在公开讨论里贴自己的日志吗？

不要提交真实日志、账户截图、凭据或可识别来源的记录。使用最小的虚构情境说明文档问题即可；合成例子仍需明确标注其性质。

### 如果发现疑似敏感内容，应在哪里报告？

按照 [SECURITY.md](../SECURITY.md) 的说明处理。只有在仓库确实启用了私密漏洞报告时才使用该入口；否则先请求建立私下沟通渠道，不要把秘密或其详细位置贴到公开讨论里。本仓库不在此虚构联系邮箱或报告服务。
