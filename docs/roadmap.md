# 公开展示路线图

[English](en/roadmap.md) · [项目首页](../README.md) · [场景导览](showcase.md)

本页描述公开展示材料可以继续完善的方向。它不是私有产品的开发排期，也不表示某项能力已经实现、部署或实盘验证；条目没有交付日期或承诺。

## 当前公开材料

| 材料 | 用途 |
|---|---|
| 中英文说明 | 介绍产品背景、能力范围与限制 |
| 概念概览与场景图 | 帮助访问者理解信息关系 |
| 合成场景、报告与事件数据 | 为文档讨论提供可阅读的虚构例子 |
| 公开范围与验证说明 | 区分展示内容与需要另行证明的事实 |
| 许可与历史许可说明 | 说明材料适用的使用条件 |

这些内容共同构成可阅读的展示包，不是可执行的交易系统。入口见 [功能说明](features.md)、[场景导览](showcase.md) 与 [PUBLIC_SCOPE.md](../PUBLIC_SCOPE.md)。

## 优先完善的方向

### 1. 阅读路径与术语

让初次访问者能顺着“项目是什么 → 关注哪些能力 → 怎样阅读示例 → 证据有哪些边界”的路径理解材料。持续统一中文、英文、图示与数据中的术语，减少同一概念的不同说法。

### 2. 更完整的合成场景

围绕多来源上下文、状态变化、信息不完整和人工复核补充虚构情境。新增例子应说明读者能观察什么，以及哪些结论仍然不能成立；不转化为真实配置或运行教程。

### 3. 文档与示例的一致性

保持示意图、场景文字和合成数据相互对应。需要时补充字段含义、阅读顺序和示例之间的关系，但不将公开数据格式描述为生产接口契约。

### 4. 更清楚的证据标注

继续明确区分能力描述、概念示意与合成例子。任何未来新增的可验证公开陈述，都应说明其适用范围和依据，不能用虚构数字补足缺失的证据。

### 5. 可访问性与阅读体验

完善图片替代文本、标题层级、移动端阅读和中英文导航。重要限制应在相关内容附近可见，不依赖读者读到页面末尾才发现。

## 可探索的展示主题

| 主题 | 希望改善的阅读体验 |
|---|---|
| 原因说明 | 更容易区分已知事实、解释与未决问题 |
| 变更前后对照 | 更容易理解一次设置讨论会影响哪些信息 |
| 报告层次 | 先看到重点，再找到相关情境 |
| 场景覆盖索引 | 清楚知道哪些问题已有合成示例，哪些仍未展示 |

这些是内容方向，不是功能上线计划，也不说明私有系统采用何种设计。

## 公开包不计划承担的内容

- 可连接账户或执行交易的运行时。
- 真实账户配置、交易参数或部署操作流程。
- 私有执行、分配、风控或故障处理的实现说明。
- 生产日志、逐笔记录、账户历史或来源研究资料。
- 以合成场景替代实盘、性能、安全或收益证据。

## 怎样提出改进建议

建议可以围绕一个明确的阅读问题展开：哪段说明不清楚、哪一种虚构情境有助于理解，或者哪些中英文表述没有对应。可优先考虑让访问者更容易区分来源、动作、结果和证据边界的改动。

新增公开材料仍应遵循 [公开范围](../PUBLIC_SCOPE.md) 与 [LICENSE](../LICENSE)。路线图的更新只说明展示内容的变化，不代表私有实现的发布。
