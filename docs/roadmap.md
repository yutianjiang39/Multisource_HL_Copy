# 路线图

这里只列值得公开的条目，不对应内部的每一次修改，也不承诺时间。

## 已具备

- 多来源跟单（按币归属，冲突时先到先得）
- 挂单镜像、原地改价、撤单跟随、吃单开仓、跟随减仓、残仓清理
- 程序内的净值回撤止损，加上独立守护进程兜底
- 运行中调参（即时 / 重建两级）与来源切换
- 实时事件推送、定时报告、AI 助手做异常分析
- dry_run 演练、多版本并存部署、滚动事故记录

## 正在完善

- **把近期修复放到实盘复核：** 竞态、部分成交、控制交接这几类修复已部署，还要用真实来源逐项确认。
- **跨路径一致性：** 同一条约束在挂单、吃单、恢复、停止各路径上表现一致，比如重建后重新镜像来源已有的挂单、新币元数据读取失败后重试。

## 计划探索

- **统一的意图与确认：** 把「想做什么」「已经发出什么」「交易所确认了什么」统一建模，让排查和恢复更直接。
- **常驻账户内核：** 增删来源、重建会话时，账户层的风控不中断。
- **解释查询：** 直接问「这张单为什么没跟」，由系统给出原因。
- **即时消息查询：** 在聊天里查看状态和持仓。

## 暂不做

- 离线回放：已经移出主体，现在只保留记录。
- 基于内存池的提前撤单：成本太高。
